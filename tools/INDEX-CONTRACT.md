# Index Interface Contract

The binding interface shared by three artifacts that must agree for a store's
stage-one index to work:

1. **`index-gen`** (producer) — derives each store's stage-one index and writes
   it into the hosting skill.
2. **the store skills' `SKILL.md` shells** (host) — reserve the region the
   producer writes.
3. **`corpus-lint`** (verifier) — fails when a committed index diverges from a
   fresh regeneration.

Guessed independently, the three diverge and integration breaks. This file is
that interface. It is a **register** — corrected in place; git history carries
its amendments.

The *content* rules for a generated index (voice, the settlement test) are
owned by [/corpus/LANGUAGE.md](/corpus/LANGUAGE.md) and are referenced here,
never copied. This file owns the *mechanism*: markers, grammar, determinism,
and the module surface the three artifacts share.

## Scope

**Index targets** — routed by index scan, one file per entry:
`decisions/`, `rules/`, `beliefs/`. These three, and only these, have a
generated index.

**Not targets** — whole-read registers that are already their own read surface,
so no index is derived and their skills reserve no generated region:

- `latches/` — `planning.md` / `closing.md` are walk tables read whole at the
  walk points (per [/corpus/latches/README.md](/corpus/latches/README.md)).
- `vocabulary/` — `terms.md` is alphabetical term blocks, read on term
  ambiguity (per [/corpus/vocabulary/README.md](/corpus/vocabulary/README.md)).

**Out of scope** — per-class grouped views (the vocabulary join-key
projection), minted only if entry scatter is observed to hurt. Not this
contract.

## The settlement test (governing principle)

[/corpus/LANGUAGE.md](/corpus/LANGUAGE.md) binds a generated index to
**activation and lifecycle fields only** — never any sentence a reader could
comply with without opening the record. The operational consequence, per store:
**the payload sentence is never emitted.** That is the `## Decision` section for
a case, the `## Duty` sentence for a rule, and the `## Claim` for a belief. A
reader who obeys an index cell has obeyed without the warrant — the defect the
index exists to make impossible.

The one payload-adjacent string an index may carry is a store's one-line
summary, and only where that store's SCHEMA mandates the summary be
non-obeyable on its own. `/corpus/decisions/SCHEMA.md` mandates exactly that;
the belief summary carries no such guarantee, so the belief index keys on
`consult-when` instead.

## The marker block (host ↔ producer)

Each hosting `SKILL.md` reserves one region per store it hosts, delimited by two
fixed comment lines. Everything between them is owned by `index-gen`; a hand
edit inside the region is a defect the verifier catches on the next run.

```
<!-- index:decisions begin — generated by tools/index-gen; do not edit between markers -->
- D-0007 · active · timeout storms upstream of a datastore stay pool-shaped until saturation is excluded
<!-- index:decisions end -->
```

- **The marker lines are fixed constants**, one pair per `StoreId`. The
  producer matches them verbatim and rewrites only the lines strictly between
  them; the marker lines themselves are never regenerated.
- **A target `SKILL.md` MUST contain its store's marker pair — exactly one,
  each on its own line.** Markers absent, duplicated, mid-line, or out of order
  is malformed: a verifier failure, never a silent skip.
- **An empty store renders an empty region**: the two marker lines adjacent,
  nothing between them.

## Store → hosting skill

| Store | `StoreId` | Hosting `SKILL.md` |
|---|---|---|
| decisions | `decisions` | `skills/cases/SKILL.md` |
| rules | `rules` | `skills/rules/SKILL.md` |
| beliefs | `beliefs` | `skills/beliefs/SKILL.md` |

## Per-store index grammar

One `- ` list line per entry, fields joined by the module constant `FIELD_SEP`
(` · `). Field values are taken verbatim from the entry (a frontmatter YAML
scalar or the `# ` title), trimmed of surrounding whitespace, single-line —
inline comments and quotes are decoded by the YAML parser, and block/folded
scalars are not index fields. A value containing `FIELD_SEP` makes the producer
throw — it never silently corrupts a line. An absent optional value renders
`(none)`.

### decisions → `cases`

Source: the `# ` summary line; frontmatter `status`, `superseded-by`.

```
- {id} · {status}{ → superseded-by when status: superseded} · {summary}
```

```
- D-0007 · active · timeout storms upstream of a datastore stay pool-shaped until saturation is excluded
- D-0003 · superseded → D-0007 · a datastore timeout storm is a pool fault until saturation is ruled out
```

Never emit: `## Decision`, `## Warrant`, `## Revisit`, `recurrences`,
`moot-when`. The summary is admitted *only* because
`/corpus/decisions/SCHEMA.md` mandates it be non-obeyable.

### rules → `rules`

Source: frontmatter `residue`, `fires-when`, `not-this`, `floor`, `status`. The
disclosed residue **leads** — per [/corpus/rules/README.md](/corpus/rules/README.md),
the index leads with residue and hook and never carries the duty sentence.

```
- {id} · residue: {residue} · fires-when: {fires-when} · not-this: {not-this} · floor: {floor} · {status}
```

Never emit: the `## Duty` sentence, nor the `# ` recognition line — the hook
(`fires-when`) routes; the recognition line is a within-record aid.

### beliefs → `beliefs`

Source: frontmatter `consult-when`, `deadline`, `status`, `postdiction`,
`superseded-by`.

```
- {id} · consult-when: {consult-when} · deadline: {deadline} · {status}{ · [postdiction] when true}{ → superseded-by when superseded}
```

Never emit: `## Claim`, `## Falsifier`, `## Watches`, `reference`/price, nor the
`# ` summary. The hook is `consult-when`; consultation keys on work-shape, not
on the claim.

## Determinism

Regeneration is byte-stable, so the verifier compares bytes:

- **Sort** by the integer suffix of the id, ascending (`D-0003` before
  `D-0010`). Entries of every status are included, status labeled — a retired
  entry stays discoverable so its successor pointer can be followed.
- **Newlines** are LF. Each data line ends with one LF; the final data line's
  LF is immediately followed by the end-marker line. An empty region carries no
  bytes between the marker lines.
- **No trailing spaces**; internal whitespace of a field value is preserved.
- **The read protocol** ("scan summaries; skip non-active unless following a
  pointer; comply from the record, never the cell") is skill prose authored
  *outside* the markers — never inside the generated region.

## The shared module (producer ↔ verifier)

`tools/index-contract.ts` is the single source of truth. Both `index-gen` and
`corpus-lint` import it; **neither reimplements parsing, rendering, or the
markers.** Reimplementation is the exact drift this contract exists to prevent.

```ts
export type StoreId = 'decisions' | 'rules' | 'beliefs';
export const INDEX_STORES: readonly StoreId[];

// store -> the SKILL.md that hosts its generated region (repo-relative)
export const INDEX_TARGETS: Record<StoreId, string>;

export const FIELD_SEP: string; // ' · ' — the one delimiter

export interface IndexRecord {
  id: string;               // 'D-0007'
  status: string;
  [field: string]: string;  // store-specific extracted fields
}

export function markers(store: StoreId): { begin: string; end: string };

// one entry file's text -> the record the index needs (frontmatter + title only)
export function parseEntry(store: StoreId, fileText: string): IndexRecord;

// deterministic content BETWEEN the markers (no marker lines), newline rules applied
export function renderIndexBlock(store: StoreId, records: IndexRecord[]): string;

// replace the region between a store's markers; throw if markers absent/malformed
export function spliceIndexBlock(skillText: string, store: StoreId, block: string): string;

// is this SKILL.md's region already current for these records?
export function isBlockCurrent(skillText: string, store: StoreId, records: IndexRecord[]): boolean;
```

- **`index-gen`** is a thin driver: for each `StoreId`, read the entry files,
  `parseEntry` each, `renderIndexBlock`, read the target `SKILL.md`,
  `spliceIndexBlock`, write it back.
- **`corpus-lint`'s index rule** reads and parses the same way, then asserts the
  markers are present and `isBlockCurrent` holds for every target — importing
  these functions, never duplicating them.

The concrete runner (tsx/node), package manager, and test tool are
implementation choices; this contract fixes only the importable surface above.

## CLI surface

- `index-gen` — write every store's region into its `SKILL.md`.
- `index-gen --check` — exit non-zero, naming the stale stores, if any region
  differs from a fresh render. Writes nothing. This is the CI form.
- `corpus-lint` — carries an `index-current` rule equivalent to
  `index-gen --check`, reusing the shared module.

## What the verifier does not check (residue)

- That the skill prose *outside* the region is honest, or that the read protocol
  is present. Presence of the region is checked; the prose around it is
  judgment.
- That the fields chosen for a store are the *right* activation/lifecycle
  fields. The grammar above is fixed by review, not by the linter.
- Entry validity (five-slot presence, frozen-path immutability, banned tells).
  Other `corpus-lint` rules own those; the index rule assumes valid entries and
  checks only regeneration currency.
