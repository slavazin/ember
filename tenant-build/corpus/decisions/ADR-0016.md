# The Article-10 Qodo gate is mechanized as an optional, bounded, post-close tool that re-reviews and re-invokes but never merges

## Context
The repository gate requires every change to flow through a pull request, a Qodo
`/agentic_review`, and the addressing of High-severity findings before a human merges.
The "address High findings" step was manual: a human posted the trigger, read the verdict,
and decided whether more work was owed. Mechanizing it raises three forces. First, the gate
governs build process — it is one of the inward-only meta concerns kept out of the shipped
layer (ADR-0003) — so its automation must not enter the tenant-agnostic layer pack. Second,
the human merge is the sole adjudicating write (ADR-0010); any automation must re-review and
re-work without ever merging. Third, a session that closes by re-triggering review, whose
re-review spawns another session that closes the same way, recurses without a bound.

## Options considered
### Option A — a shipped layer skill in the fast-loop close path
Shape: fold the gate into a `skills/` pack alongside `close`. Verdict: rejected — the Qodo
gate is build-meta (ADR-0003); a layer skill would leak process ceremony no tenant needs
into the reusable substrate.
### Option B — a separate remediation agent that owns the loop
Shape: define a separate agent type dispatched to fix findings. Verdict: rejected — the incident
responder already boots from and resumes an open PR's branch; a second agent duplicates that
boot and adds a role the separation rules (Article 3) do not require.
### Option C — an optional build-side tool wired into the tenant agent, reusing the saved agent
Shape: a `tools/` script, off by default behind a toggle, run after the close files the PR;
on an open High-or-above finding it opens a fresh session of the *same* saved agent on the
*same* branch, and it never merges. Verdict: chosen.

## Decision
The Qodo gate is a build-side tool (`tools/qodo-gate.ts`), disabled unless the `QODO_GATE`
toggle is set, run after the close files the pull request. It posts `/agentic_review`, polls
the Qodo verdict, and reads severity from the inline-comment badge joined by finding title to
the summary comment's resolution markers. On an open finding of severity High or above it
opens a remediation session of the saved incident-responder agent, via the TrueForge session
API, seeded to resume the same pull request's branch — not a separate agent and not a second
pull request. The loop is bounded by a maximum remediation-round count; past the cap the tool
surfaces the remaining findings to the human and exits non-zero. The tool never merges and
exposes no merge path. The wiring lives on the tenant agent's instructions, never in a layer
skill.

## Consequences
Keeps the automation out of the shipped layer (ADR-0003 holds) while making the Article-10
remediation step run without a human in the inner loop. Preserves the human merge as the only
admitting write (ADR-0010): the tool re-reviews and re-invokes, and stops at the round cap
rather than recursing without end. Reuses the incident responder's existing resume-the-open-PR
boot, so no second agent or role is introduced. Forecloses shipping the gate as a layer skill
and forecloses any auto-merge. Ties the gate to Qodo emitting a machine-readable severity
badge and to the TrueForge session API remaining reachable from the host that runs the tool.

## Warrant
- The gate is off unless `QODO_GATE=on`; unset, the tool prints a disabled notice and exits 0
  (as of 2026-08-29, tools/qodo-gate.ts).
- The remediation loop is bounded by `QODO_GATE_MAX_ROUNDS` (default 2): past the cap the
  decision is `exhausted`, which exits non-zero and surfaces to the human
  (as of 2026-08-29, tools/qodo-gate-lib.ts `classify`).
- The library exposes no merge, admit, or approve action; a test asserts every export name is
  free of those verbs (as of 2026-08-29, tools/qodo-gate.test.ts).
- Severity rides an inline shields.io badge (`/badge/High-…`) and resolution rides the summary
  comment's `🐞 Bugs (N)` and `✓ Resolved` markers, joined by finding title — verified against
  slavazin/ember PR #20 (as of 2026-08-29, tools/qodo-gate.test.ts fixtures).
- The two-tier push-and-merge gate this automates end-to-end is ADR-0010; the patch-to-PR host
  boundary it runs behind is ADR-0009.
- False if: TrueForge gains a native, severity-gated post-review re-invocation, making the tool
  redundant.
- False if: Qodo stops emitting a machine-readable severity badge on inline findings, breaking
  the join the gate reads.
