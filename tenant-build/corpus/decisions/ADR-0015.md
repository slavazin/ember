# A corpus deposit is signed agent-authored — a reserved author identity and Incident-* commit trailers — and rides the human's merge commit into the one shared history

## Context
The corpus deposit and the project build share one repository and one
pull-request stream (Art. 10). Build commits are human-authored and carry
`Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`; a deposit the
incident-responder produces is applied on the host by that same person and,
unmarked, is indistinguishable from build work in that stream. Article 12 rests
the demo on incident N versus incident N+k of one class read out of public git
history — a delta unreadable from a history that cannot separate agent output
from build output, nor group and time-order the deposits of a class. Git already
models the split the deposit needs: the author produced a change, the committer
applied it, a merge commit records a third party admitting it — the propose /
apply / adjudicate parties, without invention. The corpus write leaves the
sandbox as a patch the host applies (ADR-0009), so the author and trailers the
sandbox sets on the candidate commit survive `git am` onto the branch, and a
merge commit carries them into the trunk.

## Options considered
### Option A — separate the tenant corpus into its own repository
Shape: move `tenant-incident/corpus/` to a second repository so every pull
request there is agent output by construction and needs no marking — read as the
end of Art. 7's layer/tenant separation. Verdict: rejected for the submission —
Art. 7 separates the tenant into its own *tree*, not its own repository; a second
repository fractures the single public history Art. 12's demo reads across, is
ceremony over a genesis-empty tenant corpus, and adds nothing to the reusability
claim `tenant-build` already demonstrates in-tree. Not foreclosed as the
post-submission end state when a second tenant needs hard isolation.
### Option B — keep the corpus in-tree and sign the deposit
Shape: the sandbox builds the candidate commit under a reserved author identity
and a block of `Incident-*` trailers; the host applies it on an `incident/`
branch and opens a `corpus-deposit`-labelled pull request; the human admits it
with a merge commit. Verdict: chosen — one public history, cheap, and durable:
the author and trailers survive the merge and stay queryable.

## Decision
A corpus deposit is marked at three layers. The durable, post-merge marker is the
candidate commit itself: its **author** is the reserved identity
`incident-responder <incident-responder@ember.invalid>`, disjoint from the human
author of build commits and from the `Co-Authored-By: Claude Opus 4.8` build
trailer, and it carries a trailer block placing the deposit in the learning arc —
`Incident-Id`, `Incident-Class`, `Corpus-Store`, `Deposited-By:
incident-responder`, and an optional derived `Loop-Iteration`. The **committer**
of that commit is the human host that applied the patch, and the admitting
**merge commit** is the human's; the author / committer / merger split is the
git-native encoding of the agent proposing, the host applying, and the human
adjudicating (Art. 2, Art. 3) — an agent-authored commit does not make the agent
a committing party. The surface markers are a reserved `incident/<incident-id>`
branch prefix and a `corpus-deposit` pull-request label, with a title and body
naming the incident and the gate. A deposit is admitted by a merge commit that
preserves the candidate commit's author and trailers and records the human's
adjudication; a squash merge, which collapses author and trailers into the
merger's own commit, does not admit a corpus deposit.

## Consequences
Makes every agent deposit separable from build work by author
(`git log --author=incident-responder`), groupable by class and orderable by
author-date (`--grep='^Incident-Class:'`), and reachable by label
(`gh pr list --label corpus-deposit`) — the queries Art. 12's read-out needs.
Sets the durable marker once, in the sandbox, where the content is produced; the
host helper and the pull request only restate it, so a surface marker that drifts
from the commit is a detectable inconsistency, not a silent mislabel. Binds a
`corpus-deposit` admission to a history-preserving merge; a squash admission
lands the deposit unsigned in the trunk and is disallowed. Leaves
`Loop-Iteration` derivable from author-date ordering of a class rather than
hand-maintained (Art. 8), so a stale ordinal cannot misreport the arc.
Forecloses nothing about a future separate-tenant repository (Option A), the end
state when isolation rather than one-history demo is the goal.

## Warrant
- The corpus write leaves the sandbox as a patch the host applies with
  `git am`, which preserves the patch author and message trailers (as of
  2026-08-29, /tools/patch-to-pr.sh once promoted; ADR-0009).
- The build's commit signature is a human author plus `Co-Authored-By: Claude
  Opus 4.8 <noreply@anthropic.com>`; the reserved agent author and `Incident-*`
  trailers are disjoint from it (as of 2026-08-29, the merged pull-request trail
  in /README.md).
- The repository admits pull requests by merge commit, reachable from the trunk
  (as of 2026-08-29, the merge commits in the /README.md pull-request trail).
- False if: the repository adopts squash-merge for `corpus-deposit` pull
  requests, collapsing the candidate commit's author and trailers — then the
  marker moves into the squash commit's message and merge author, or Option A
  reopens.
- False if: the harness gains a clean in-sandbox push (ADR-0009's own
  falsifier), moving where the author and trailers are set from the patch onto a
  direct push — the markers hold, their set-point moves.
- False if: a second incident tenant needs hard isolation from the layer's
  history, which reopens Option A.
