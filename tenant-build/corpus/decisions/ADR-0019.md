# The host filing path carries the close-out record — folded into the PR and committed under the reserved author — and files a candidate-less quiet close on the record alone

## Context
A fast-loop close-out is a durable record whether or not the session drafts a candidate:
the consulted-entry dispositions, the report metadata (`steps`/`disposition`/`forecast_hit`),
and the `latch-walk:` attestation are content enough (skills/close/SKILL.md). But the host
filing path did not carry that content. `corpus-write` exports the deposit with
`git format-patch -1 --stdout` — the single candidate commit — and `tools/patch-to-pr.sh`
derives the pull-request body from that commit's `Incident-*` trailers alone. The close-out
record's own content lives in the branch work product, not in the one exported commit, so it
never reached the pull request the next boot and the slow loop read. Worse, a candidate-less
quiet close had no host path at all: `patch-to-pr.sh` rejected any patch carrying no marked
deposit commit, so a quiet session's dispositions and attestation could not be filed. PR #27
hardened the three fast-loop skills and disclosed exactly this as residue, pointing at the
host side (Article 8). Those three skills are under concurrent change and off-limits here to
avoid a merge collision, so the reconciliation is host-side — in ADR-0009's filing path — not
in `corpus-write`'s export.

## Options considered
### Option A — widen `corpus-write`'s export to a commit range
Shape: change `corpus-write` to `git format-patch` over `origin/main..HEAD` so the close-out
commit rides the patch under a sandbox-set marker (ADR-0015), and let `git am` replay it.
Verdict: rejected at this stage — `corpus-write` is one of the three skills under concurrent
change (PR #27) and editing it here collides; and `-1` is the ADR-0015 candidate contract, so
widening the export is a change to make once that skill settles. Not foreclosed — it is this
decision's falsifier.
### Option B — the host filing path carries the record
Shape: `patch-to-pr.sh` accepts a `--close-out <record>` retrieved over ADR-0009's
file-download channel, commits it under the reserved author, folds it into the pull-request
body, and admits a candidate-less quiet close on the record alone. Verdict: chosen —
host-side, touches no skill, and leaves the candidate's ADR-0015 marking untouched.

## Decision
`tools/patch-to-pr.sh` accepts an optional `--close-out <record>` alongside a candidate
patch, and a `--close-out <record>` with no patch (a quiet close). The record — retrieved
from the sandbox branch over the same ADR-0009 file-download channel as the patch — is
committed to the branch at `tenant-incident/incidents/<incident-id>/close-out.md` and folded
into the pull-request body, so its content rides the human's merge into the one shared history
(ADR-0015) that the next boot and the slow loop read. The close-out commit is authored by the
reserved `incident-responder` identity, the host is its committer (ADR-0015's author/committer
split), and it carries `Incident-Id`, `Deposited-By: incident-responder`, and
`Close-Record: true` — and deliberately no `Incident-Class` trailer: a close-out is grouped by
the work-shape it declares, not the class-grouping trailer (skills/consolidate/SKILL.md), and
a class trailer would double-count the incident in the class read-out where a candidate
already carries it. The candidate deposit's ADR-0015 marking is untouched: the anti-smuggling
author-and-trailer guard runs over the applied patch commits only, before the host adds the
close-out commit; the host-built close-out commit is trusted content, not patch-borne, and is
admitted on its own terms. A quiet close derives the incident id (and an advisory class) from
the record's frontmatter, and the id is validated to a safe token before it names a path or a
branch. Both forms file a `corpus-deposit`-labelled pull request; the merge stays the human
gate (ADR-0007), still a merge commit, not a squash.

## Consequences
The dispositions, the report metadata, and the `latch-walk:` attestation reach the pull
request — durably in git history as a committed record and legibly in the pull-request body —
closing the PR #27 residue. A quiet session that drafts no candidate gains a first-class host
path: its close-out is a `corpus-deposit` pull request, separable by the `incident-responder`
author, so the slow loop's disposition telemetry — the bulk of it from quiet sessions — is not
dropped for lacking a deposit (skills/consolidate/SKILL.md). The marker set-point for the
close-out record is the host: it transcribes the record's frontmatter into the commit trailers
and restates the reserved author, unlike the candidate whose marker is sandbox-set (ADR-0015).
That is the cost of leaving `corpus-write`'s `-1` export unchanged; the marker *values* are
still sandbox-produced (the record's frontmatter), the host only re-encodes them. Reuses
ADR-0009's retrieval channel, so the sandbox still never authenticates outward. Forecloses
nothing about Option A: once `corpus-write` can export the close-out commit itself, the record
rides `git am` under a sandbox-set marker and the host stops committing it.

## Warrant
- `git format-patch -1 --stdout` exports only the candidate commit, and the host derived the
  pull-request body from its trailers alone (as of 2026-08-29, skills/corpus-write/SKILL.md
  Filing section; tools/patch-to-pr.sh).
- The residue this closes is disclosed in the close skill's "The close runs to completion"
  section (as of 2026-08-29, PR #27, skills/close/SKILL.md).
- The slow loop reads a quiet close keyed by the work-shape it declares and never gates
  disposition telemetry on a deposit (as of 2026-08-29, skills/consolidate/SKILL.md, "What
  this pass reads").
- The record leaves the sandbox over the same host file-download channel as the patch
  (ADR-0009); the candidate's signed-marker contract is ADR-0015; the two-tier approval and
  merge gate is ADR-0007.
- False if: `corpus-write`'s export widens beyond `git format-patch -1` to carry the close-out
  commit in the patch — then the record rides `git am` under a sandbox-set marker and the host
  stops committing it (Option A reopens; the marker set-point moves back to the sandbox).
- False if: a squash merge is adopted for `corpus-deposit` pull requests, collapsing the
  close-out commit's author and trailers into the merger's own commit (shared with ADR-0015's
  falsifier).
