# A sandbox remediation is gated at the corpus pull-request merge, not by a harness tool-approval

## Context
The harness approval pauses a tool call for human confirmation, but it fires only on
MCP-server tool calls; the sandbox `exec` and the other system tools carry no approval policy.
A remediation that runs commands in the sandbox therefore cannot be gated by a per-tool harness
approval. ADR-0007 already makes the corpus pull-request merge the adjudicating human gate for
a permanent write, and the sandbox is disposable — its only durable output is the corpus write
it emits.

## Options considered
### Option A — express risky remediation as approval-bearing MCP tools
Shape: wrap every risky remediation as an MCP tool carrying `require_approval`, so the harness
pauses before it runs. Verdict: rejected — it forces every sandbox action through an MCP
wrapper, still leaves raw `exec` ungated, and carries the wrapping as standing overhead for
partial coverage.
### Option B — the corpus pull-request merge is the gate
Shape: a remediation's durable effect reaches the estate only as a corpus write, already gated
at the pull-request merge (ADR-0007); the sandbox is discarded. Verdict: chosen — the gate that
adjudicates the durable write already covers the effect that matters.

## Decision
A sandbox remediation is not gated by a harness tool-approval; its durable effect on the estate
lands only through a corpus write, adjudicated at the pull-request merge (ADR-0007). Approval-
bearing MCP tools are not required to make a remediation safe, because the sandbox is disposable
and its only permanent output is the gated corpus write.

## Consequences
Enables a remediation to run in the sandbox without an MCP wrapper on every action, resting its
safety on the disposability of the sandbox and the merge gate rather than on per-tool approvals.
Forecloses treating a harness tool-approval as the control that makes a sandbox action safe: a
remediation whose effect can escape the sandbox without passing through a corpus write has no
gate and is redesigned to route through one.

## Warrant
- The harness fires approvals only on MCP-server tool calls; the sandbox `exec` and system
  tools accept no approval policy (as of 2026-08-28, TrueForge v0.1.4).
- The harness integration is the designed path, not yet verified in this repository; the v0.1.4
  measurement above is external evidence, with no in-repo verification anchor yet (as of
  2026-08-28, /README.md Track B status).
- The adjudicating merge gate this rests on is ADR-0007.
- False if: a remediation's effect reaches the estate by a path that is neither a corpus pull
  request nor otherwise human-gated — for example a sandbox tool that mutates external state
  directly.
- False if: a harness release extends approvals to system and `exec` tools, making a per-tool
  gate available for sandbox actions.
