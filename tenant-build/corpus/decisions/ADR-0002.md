# Each tenant is a guest under its own tenant-*/ tree; the layer sits at the repository root

## Context
The flat file-kind seam leaves the reusability claim undemonstrable — a reusable layer is
falsified the moment tenant knowledge cannot be pointed to as separate — and leaves a seam
check no tenant tree to derive tenant vocabulary from.

## Options considered
### Option A — keep the flat root, distinguish by file kind only
Shape: ADR-0001's seam. Verdict: rejected — the boundary is invisible and unscopeable.
### Option B — a tenant tree per guest
Shape: the layer at the root, each tenant under `tenant-*/`. Verdict: chosen.

## Decision
The repository root is the reusable layer; each tenant is a guest under a `tenant-*/`
tree holding its own entries. A second tenant installs by adding a tree and touches no
layer file.

## Consequences
Makes the layer/tenant boundary visible and lets the seam check derive the tenant term set
from the tenant tree. Forecloses tenant entries at the root.

## Warrant
- The seam check derives its tenant terms from `tenant-incident/scenarios` and greps only
  layer files (as of PR #7, tools/corpus-lint.ts `checkSeam`).
- The incident scenarios live under `tenant-incident/scenarios/` (as of PR #5).
- False if: a tenant's entries must reach into a layer file to install.
