# Boot recovers cross-session learning from the corpus, not from a prior pull request

## Context
Learning is corpus-carried: a fresh session recovers everything from the admitted
stores, which is the load-bearing "improves across sessions" claim. The boot
protocol had coupled two unrelated recoveries into one step — resuming genuinely
un-merged in-flight work (continuity), and reading the last merged pull request's
close-out (learning). The second is wrong on its own terms: a merged candidate is
already an admitted entry in the stores, so re-reading the pull request duplicates
the corpus; and reaching into an open, un-merged candidate pull request to apply it
would bind knowledge the human has not admitted (Article 2). A boot that must read a
prior pull request to learn contradicts the corpus-carried thesis.

## Options considered
### Option A — boot reads the last merged PR's close-out plus open un-merged work
Shape: one recovery step spanning a prior merged pull request and open branches.
Verdict: rejected — couples continuity with learning; re-reading a merged pull
request duplicates the corpus, and reaching into an open candidate pull request
would bind un-admitted knowledge.
### Option B — boot recovers learning only from the corpus; work-recovery is scoped to un-merged in-flight work
Shape: the shape-matched stores carry learning; the boot resumes only work left
un-merged on a branch. Verdict: chosen.

## Decision
The fast-loop boot recovers cross-session learning from the admitted corpus — the
constitution, the shape-matched stores, and the planning latches — never from a
prior pull request. The boot's work-recovery is scoped to resuming work left
un-merged on a branch; a merged pull request's payload is read from the stores, not
from the request. A session that finds no un-merged work still boots whole from the
corpus.

## Consequences
Enables a self-contained fast loop whose only cross-session channel is the
human-gated corpus. Forecloses recovering learning from a prior pull request, and
forecloses binding a candidate before its merge admits it.

## Warrant
- The boot step reads open un-merged work only; learning loads from the shape-matched
  stores (as of 2026-08-28, skills/session/SKILL.md).
- Article 4 names the admitted corpus as the cross-session memory, not a prior pull
  request (skills/constitution/SKILL.md).
- False if: a required boot input has no home in the corpus and can be recovered only
  from a prior pull request.
