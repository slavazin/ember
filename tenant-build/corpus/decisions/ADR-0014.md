# The working session keeps a consultation record; the fresh close dispositions from it

## Context
Splitting the close-out to fresh context (ADR-0011) severed the closer from the
implementation's consultation history. The close must record a disposition for every
consulted entry, including the ones consulted and set aside
(`considered-not-applicable`). Applied entries shape the diff and are inferable; a
considered-and-set-aside entry leaves no trace there. A fresh closer that reconstructs
the consultation set from the diff silently drops exactly that signal — and the
dispositions are the telemetry the slow loop promotes from, so the loss is invisible
until promotion starves.

## Options considered
### Option A — the working session records consultations as it works; the close reads them
Shape: each consulted entry is written into the work product on the branch as the
consultation happens; the fresh close reads that record and assigns dispositions.
Verdict: chosen.
### Option B — scope the disposition duty to git-reachable evidence, disclose the rest as residue
Shape: the close dispositions only what the diff and the plan-time attestation carry;
considered-and-set-aside consultations not otherwise recorded are a disclosed loss.
Verdict: rejected — it designs the slow loop's telemetry to be incomplete.

## Decision
The working session keeps a consultation record in the work product on the branch —
each entry it consults, marked applied or considered, written as the consultation
happens. The fresh-context close reads that record and records the final disposition
for every entry in it; it does not infer the consultation set from the diff. The
working session supplies the set; the close assigns the disposition. The record is
work-product content that rides the branch and the pull request — not a separate jot
pile or session-log store (ADR-0006 stands).

## Consequences
Enables complete disposition telemetry under a fresh-context close. Forecloses a close
that reconstructs consultations from the diff, and forecloses treating the record as a
standing store outside the pull request.

## Warrant
- The `session` skill carries the "Keep the consultation record" duty, and the `close`
  skill's step 1 reads that record rather than the diff (as of 2026-08-28,
  skills/session/SKILL.md, skills/close/SKILL.md).
- False if: the work product's consultation record is discarded before close, or a
  close is required to run without reading it.
